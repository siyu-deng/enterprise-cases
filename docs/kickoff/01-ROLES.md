# 角色输入输出与验收

### 项目协调

维护本轮范围、依赖、约定版本和整体验收，协调共享文件与联调。

输入：
- 用户当前目标与项目现状
- 各角色交付、阻塞和验证证据

输出：
- 任务分工、依赖与启动顺序
- 共享资源/文件归属表
- 局部更新的项目状态与整体闭环验收记录

验收标准：
- 每项本轮任务都有负责角色、交付物、状态和下一步
- 接口/设计变更已同步受影响角色
- 已实现、已验证、已部署和业务验收分开记录

交接给：用户与受影响角色

### 商业价值

明确服务对象、问题、价值与收益/成本假设，决定本轮验证什么。

输入：
- 目标用户、已有业务与资源约束
- 现有收入/成本事实与用户反馈；未知项如实列出

输出：
- 用户问题与价值主张
- 收益/成本假设及验证方式
- 本轮成功条件、失败条件与证据缺口

验收标准：
- 事实、假设与推断可区分
- 验证方式与时间/成本约束相容
- 没有把部署、技术演示或预测数字当作商业结果

交接给：市场研究、产品与用户

### 市场研究

用有来源的用户、竞品和替代方案证据回答本轮市场问题。

输入：
- 目标人群、业务问题与待验证假设
- 已有研究、来源与时间边界

输出：
- 可追溯的来源与观察日期
- 竞品/替代方案及用户场景比较
- 机会判断、样本限制和后续验证建议

验收标准：
- 关键事实有具体来源和日期
- 结论不超出样本与证据
- 研究结果能影响产品范围或商业假设，而非资料堆积

交接给：商业价值与产品

### 产品定义

将用户目标转成可实现、可验收的最小业务闭环。

输入：
- 商业/市场证据及用户当前决策
- 已有业务规则、限制和反馈

输出：
- 用户流程与本轮范围/优先级
- 输入、业务规则、状态变化、权限和异常
- 成功/失败/边界验收案例及前后端接口需求

验收标准：
- 核心闭环从触发到结果完整
- 规则和关键未知项足以让设计与后端分别推进
- 验收案例有具体前提、输入与期望结果

交接给：设计、前端、后端与测试

### 设计系统与布局

在业务界面实现前建立可查看且可落地的设计系统与布局状态。

输入：
- 产品规则、内容密度与核心用户任务
- 已有设计资产、组件和当前技术约束

输出：
- 设计工具或独立网页中的颜色/字体/间距/按钮等体系
- token、组件和统一开源图标映射
- 占位图布局、响应式、加载/骨架/空数据/错误等状态

验收标准：
- 展示可查看，不能只交形容词或文档
- 布局用实际长短内容检验，文字留白清晰
- 每个元素帮助任务、理解、操作或必要识别；删除无用文案
- 适合的现成组件/开源方案已研究并复用

交接给：前端与测试

### 前端实现

按产品、设计系统和接口约定实现可操作的完整界面。

输入：
- 产品规则与验收案例
- 可查看的设计系统、布局和状态
- 接口字段/请求响应/权限/错误约定

输出：
- 统一组件、样式 token 与图标的页面
- 加载、空、错、禁用和提交反馈等相关状态
- 测试数据切换、真实接口联调和必要验证证据

验收标准：
- 业务页面实现前已核对设计体系、占位布局和完整状态
- 真实接口下的关键交互可操作并符合约定
- 测试数据效果与真实链路验证分别报告
- 不私自更改接口字段或堆叠无用文案

交接给：后端联调、测试与协调

### 后端实现

实现真实业务规则、权限、数据与接口，并承担接口真源维护。

输入：
- 产品规则、业务状态和验收案例
- 数据/权限边界与现有运行环境
- 与前端共同确认的接口约定

输出：
- 可校验的接口定义与成功/失败示例
- 业务逻辑、权限校验和持久化
- 关键写操作的重复提交/失败恢复及相称验证
- 启动方式、环境依赖和联调证据

验收标准：
- 字段、状态、权限与错误行为符合共同约定
- 可信服务执行关键规则，数据不因客户端绕过而失守
- 关键成功及失败路径有实际验证
- 接口变更更新真源并同步消费者

交接给：前端联调、测试与部署

### 测试与验收

独立检查候选版本是否符合业务规则，定位失败并报告覆盖缺口。

输入：
- 产品验收案例与设计/接口约定
- 前后端候选版本、环境和数据边界

输出：
- 核心成功、主要失败与边界的实际检查
- 可复现的问题、归因线索和证据
- 通过/失败/未测范围与剩余风险
- 按阶段安排的基础性能或后续优化事项

验收标准：
- 证据对应具体版本与环境
- 至少核对真实闭环，不能只接受实现者自述
- 未测和受阻明确列出
- 权限、资金及真实数据修改按风险验证；不强制每次小改完整审计

交接给：产品、修复负责角色与部署

### 运维与部署

准备并在授权范围内交付可核对、可恢复的目标环境版本。

输入：
- 候选版本与测试结果
- 当前可用的目标环境、依赖及配置引用
- 生产发布范围、授权与恢复要求

输出：
- 版本、部署步骤、依赖和配置说明
- 与风险相称的恢复/回滚方式
- 授权发布后的真实入口核对及阶段性能结果
- 后续 CI/CD 建设事项

验收标准：
- 环境和设备当前可用，不能沿用历史主机假设
- 生产动作有授权，失败可定位和恢复
- 实际部署版本与核对证据一致
- 部署完成与业务/用户验收分别记录；CI/CD 可分阶段建设

交接给：测试、协调与用户
